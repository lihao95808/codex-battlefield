# Codex Battlefield 验收面独立 SPEC

状态：执行中（spec 定稿 → 实现 → 自测）
续跑锚点：`PLAN-STATUS.md`

## 1. 动机（现状事实）

| 事实 | 含义 |
|---|---|
| 树的完成条件是"入站债务为空 + 整合验收通过"，而**验收判据由同一棵树的 agent 可以改**（目标工程里的测试、脚本、门禁声明都在它可写的范围内） | 产出方**能改自己正要通过的考卷**——这是体系里最深的结构洞 |
| worker / verifier / acceptance 现在是**同一个模型**（`kind` 没流到模型选择处） | 无法做"便宜 worker + 强验收"的配比，也就无法用 flash 级模型吃大工程 |
| "300% 能完成"是**纯自评**，没有任何历史校准 | 拆不拆全靠当场感觉；同一个模型总是过于自信时，没有数字能戳破它 |
| R5 已有"产物指纹基线"机制（`regression.py` + `node_meta` 存基线 + 债务上浮） | 验收面冻结**不需要新机制**，复用同一套：指纹 + 版本 + 债务 |

目标一句话：**让"裁判"独立于"选手"，并且让这件事有可机器核对的判据。**

## 2. 非目标

- 不做多租户/多机隔离（那是 R2 的范围）。
- 不引入"外部裁判模型"这一层（先解决同模型不同角色的分层）。
- 不立刻上"自评过低强制拆分"的阈值策略：先**采集**，阈值是政策决定（见 §6 未决）。
- 不阻止人改验收面——**人**改是合法的（那是改需求）；要拦的是**产出方自己改**。

## 3. A 部分：验收面冻结与防篡改

### 3.1 什么叫"验收面"

**验收面 = 宪法里显式声明的、用来判"这棵树做成了没有"的那些文件**（测试、校验脚本、门禁声明）。
落在宪法 `data` 的 `acceptance_surface: [相对路径]`。

- **未声明**（缺键或空数组）= 不判。看板与报告必须显示"未声明验收面"——不许把"没声明"读成"已通过"。
- 声明是**相对根目标**的 posix 路径；绝对路径与 `..` 一律**不参与**（与 `changed_files`、判据路径同一条边界规则）。

### 3.2 冻结

- 冻结时机：**宪法锁定**（`lock_constitution`）与**人工修订**（`amend_constitution`，本来就要 `actor` 与 `reason`）。
  两者都是人的动作——这是刻意选的：把"改考卷"这件事收敛到"人才能做"。
- 存处：树根节点的 `node_meta["acceptance_surface"] = {version, frozen_at, frozen_by, digests: {path: digest}}`。
  复用 `utils.path_digest`（文件 `sha256:` / 目录 `tree:`）与 R5 同源，不新增表、不加列。

### 3.3 比对与阻断

在**父节点整合验收之前**（与 R5 的回归门禁同一位置）比对当前指纹与冻结指纹：

| 情况 | 严重度 | 理由（失效方向写明） |
|---|---|---|
| 面文件内容变了 | **blocking** | 这就是"改考卷"。无条件阻断，与档位无关 |
| 面文件没了 | **blocking** | 消失比改动更彻底 |
| 面文件**读不到**（占用/权限） | **不判定**（单列 + 事件） | 读盘失败不是"改了"——把瞬时占用当成篡改，会让人把门禁关掉 |
| 未声明面 / 面路径非法 | **不判定** | 判不了就说判不了；不拿"没声明"当通过 |
| 面恢复了（内容又对上冻结值） | 债务按**事实**清掉 | 与 R5 同源：可核对的事实，不是"谁完成了什么" |

- 债务类型 `acceptance_surface_tampered`，幂等键绑**路径**（`acceptance_surface_tampered:<node>:<path>`），
  与 R5 一样进 `REVIVABLE_TYPES`：冻结基线前进（人工重新冻结）之后再次被改，是**另一件事**，必须重新阻断。
- 阻断走**既有**的 `_obligation_gate`（不新造门禁）；连续拦下超过 `obligation_gate_max_refusals` 仍升级人工。

### 3.4 已知限制（如实写下）

- 本地 API 是无鉴权的：**能跑 curl 的 agent 理论上可以自己调用 amend**。本 spec 只保证"改验收面会留下
  冻结指纹、且改动会被阻断债抓住"，不保证"agent 完全碰不到那条路"。真正的隔离属 R2。
- 面的**语义**（这条测试是否真的在测需求）管不了——那是 §A 部分（需求→证据追溯矩阵）的范围。

## 4. B 部分：角色异构（按 `kind` 分层模型）

- 新增按角色的模型/推理档：`codex_model_{constitution,planner,worker,verifier,acceptance}` 与
  `codex_reasoning_effort_*`，env 形如 `CODEX_BATTLEFIELD_CODEX_MODEL_ACCEPTANCE`。
- `kind` 流到参数构建处：`_codex_exec_args(..., kind=)`；缺省回退到全局 `codex_model`。
- **一条硬约定**：`acceptance` 与 `constitution` **不得**被配成比 worker 更弱的档——这是"用便宜模型干活、
  用强模型验收"的前提。实现上不做自动纠正（那会静默改配置），而是在 `watchdog/state` 里**报出来**
  （`model_tier_warnings`），让人看见。
- 收益：这是"flash 级 worker + 强 acceptance"从"想法"变成"可配"的唯一入口。

## 5. C 部分：自评校准（先采集，不上阈值）

- 口径：节点自称"300% 可完成"→ 若它随后**验证失败**或**转父节点**，就是一次**过度自信样本**。
- 采集（不新增字段，全部由现有列聚合）：按 `kind`/深度分桶，报 `claims`、`failures`、`overconfidence_ratio`。
- 只做读数：**不**据此自动拆分、不自动降级、不自动加债。理由：自动动作需要"多低的比率才算过于自信"这个
  政策输入，而政策不该由实现方悄悄定下来（见 §6 未决）。

## 6. 验收（可反驳）

| 编号 | 判据 | 怎么反驳 |
|---|---|---|
| V1 | 冻结后改动面文件 → 父节点**不得** `done`，且理由**点名路径** | 造一棵树：锁宪法 → 改面文件 → 跑验收 |
| V2 | 面文件**读不到**时**不**阻断，但事件里写明"未判定" | 用占用/权限模拟 |
| V3 | 未声明验收面时**不**阻断，但状态里显示"未声明" | 不声明跑一遍 |
| V4 | 面恢复后债务按事实清掉，节点可 `done` | 恢复内容再验收 |
| V5 | 按角色模型：`..._MODEL_WORKER` 与 `..._MODEL_ACCEPTANCE` 同时设置时，两次调用的命令行里模型名**不同** | 贴出两次 command 行 |
| V6 | 未设置任何角色档时，行为与今天**完全一致**（回退全局） | 现有 776 例不降 |
| V7 | 校准读数是**纯聚合**：不产生债务、不改状态 | 断言状态与债务数不变 |
| V8 | 不改既有行为：`pytest` 0 failed 且 passed 数不降 | 与 A1 同门槛 |
