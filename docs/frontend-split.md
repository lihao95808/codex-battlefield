## 0.5 长列表虚拟化（P5-2 最后一项）

`web/src/virtualization.ts`：一个**纯函数** `windowTasks()`，把要交给
`layoutBattlefield(...)`（elkjs）的任务切成有界窗口（默认 400 个节点）。

**为什么切在布局之前**：代价不在 DOM 数量，而在"把节点交给 ReactFlow 之前的布局计算"
—— 千节点时那是主线程上的大头，而 ReactFlow 自己的 `onlyRenderVisibleElements`
管不到它。装一个第三方虚拟滚动库只会和 ReactFlow 的坐标系统打架。

三条规矩（`virtualization.test.ts` 13 例，变异验证：去掉上限 → 6 例红，
不保祖先链 → 1 例红）：

1. **窗口外的东西要出声**：返回 `omitted`，界面上写"另有 N 个节点被窗口挡住"。
   悄悄丢节点比慢更坏 —— 用户会以为树就这么多。
2. **选中节点连同它的祖先链永远在窗口里**（只保自己会让它在树上悬空，而用户正盯着它）。
   `limit` 记的是**请求的上限**，祖先链可以把真实数量撑过它 —— 两个数都返回，免得读错。
3. **"关掉虚拟化"与"窗口为 0"是两件事**：`limit <= 0` 表示不限制（返回全部），
   不是"一个都不要"。

`visibleNodeCount` 用的是**完整**的 `visibleTasks`，旁边单独显示"画布渲染了多少"。
把统计也改成窗口大小，就等于悄悄改掉用户读到的数 —— 那是**用显示数字掩盖省略**。


判据：`format.test.ts`（36 例）、`polling.test.ts`（11 例）、`fileSize.test.ts`（11 例）。

## 0. 这一轮是怎么拆的（以及为什么手写扫描器不行）

三次手写"字符配平"扫描器，三次都错，错法一个比一个隐蔽：

1. **逐行扫** → 模板串 `` `${x} 小时` `` 里的 `}` 被当成块结尾，`App()` 被判成 500 行结束；
2. **改成跨行状态机** → 模板串里的 `}` 仍被当成"不匹配的括号"；
3. **修好模板串** → "从声明找第一个配平的 `}`"找到的是**体内第一个块**的结尾
   （`WatchdogPanel` 被判成 1965 行结束，真实 2371）。

结论写进了 `web/_ts_extract.mjs`（保留这个工具，它记录了这三条）：
这类活交给 `typescript` 的解析器，它是这个仓库本来就有的依赖。

### 拆的过程本身也踩了四个坑（都留了注释）

* **改名只改引用、没删原文**：`const view = useBattlefieldController();` 插进去了，
  但 688 行状态**还在** App 里。构建**通过**（`view.xxx` 成了未定义属性），
  运行时才炸 —— 比编译错更坏。所以删除必须由工具做，不能靠"改了名就等于搬走了"。
* **`App.tsx`（5 万字符）经 stdout 传给 Python 会被截断**：JSON 解析出来是空串，
  表现成"找不到 App() 体内第一条语句"。改成让 Node 直接写文件。
* **新行插在"最后一个 import 之后"** → 插进了多行 `import type { ... }` 的中间
  （`TS1003 Identifier expected`）。改成插在**第一个 import 之前**。
* **"JSX 自己声明的名字"判据写得太宽**：`\(\s*(\w+)\s*[,)]` 把
  `statNumber(visibleStats, 'total')` 里的 `visibleStats` 也当成了 JSX 局部变量，
  于是它既没进 hook 的 return、也没被改名。收紧成只认真实参数表。

## 2. 轮询：从"每 10 秒"到"看不见就不拉"

### 原来的问题

```ts
const interval = window.setInterval(() => loadTree(), 10000);   // ❌ 从不停止
```

于是**页面切到后台、甚至整晚开着没人看的时候，它仍然每 10 秒打一次 API**。
而 `/api/tree` 在千节点下要 130ms（`docs/scale-baseline.md`）—— 无人看护时持续占资源。

### 现在

* **SSE 是主通路**：树有变化时后端推事件，2 秒防抖后拉一次（一次状态转换常连着好几条事件）；
* **轮询是兜底**：SSE 静默断开时（代理掐连接、网络抖动）没它界面会一直显示旧数据而没人知道。
  所以留着，但间隔放到 60 秒；
* **页面不可见时完全不拉**：切回可见时**立刻**拉一次，所以看不到旧数据。

**为什么不直接全换成 SSE**：一棵千节点树的荷载是 640KB，推流的性价比很低，
而"用户在看的时候才拉"本来就是这个界面的真实使用形态。
真正省掉请求的是**可见性**，不是传输方式。

### 一个必须说清的取舍

不可见时完全不拉意味着：后台开一整晚，回来看到的是最后一次拉到的数据。
但那没关系 —— 切回可见时立刻拉一次，中间那段"在后台看旧数据"没有意义。

## 3. 棘轮判据（`fileSize.test.ts`）

ROADMAP 的判据是"单文件不再超 500 行"。但**现在直接卡 500 会红一片**，
而"允许长期红着的判据"很快会变成"所有人学会忽略它"。

所以用**棘轮**：给每个超标文件记一个**只许减少**的预算。

| 文件 | 预算 | 为什么还没达标 |
|---|---|---|
| `App.tsx` | 2715 | 纯逻辑已抽出；剩下的是 React 组件与其 props/状态 |
| `types.ts` | 948 | 纯类型文件，按领域拆是下一步（无逻辑，风险低） |
| `api.ts` | 833 | 薄封装，同上 |
| `StewardPanel.tsx` | 565 | 面板自带对话状态 |

四条规矩（缺一条棘轮就退化成装饰）：

1. 文件变大超过预算 → 红（想扩容必须显式改测试文件，那次改动会被 review 看见）；
2. 超过 500 行的文件**必须**登记预算（新文件直接受约束）；
3. `BUDGET_TOTAL` 与逐项之和对得上（两处数字不许漂移）；
4. 达标的条目要**删掉**（预算表是"还没拆完"的清单，不是"曾经很大"的历史）。

## 4. 过程中踩到的三个坑

### 4.1 批量删块：按行号删会整体偏移

第一次按行号删，而前面刚加过一行 import —— 所有行号偏移，删错了地方。
→ 改成**按锚点找**。

### 4.2 批量删块：`};` 是顶格的

"收到下一个顶格行就停"的写法在 `const x: Record<...> = {` 的收尾 `};` 处停下，
剩下的条目变成游离语句（一次 20+ 个 TS1128）。
→ 改成**按花括号配对**收块。

### 4.3 索引改函数调用：只换了前半截

把 `statusLabels[x]` 换成 `statusLabel(x` 却留着 `]`，于是成了 `statusLabel(x]`。
报错位置在别处（JSX 属性值上），很难一眼看出根因。
→ 用**正则一次换掉配对的括号**；参数里含嵌套括号的（`String(x) as T]`）手工修。

**三条共同的教训**：批量改写前先确认能一键回退（`git checkout -- <file>`），
并且**改完立刻跑类型检查** —— 这三处都是类型检查当场抓到的。
